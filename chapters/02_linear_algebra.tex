\chapter{Linear Algebra Foundations}

\section{Why this chapter matters}
This chapter is not a general linear algebra course in the traditional sense. Its purpose is to explain why the central constructions of post-quantum cryptography are built on linear algebra. In particular, we want to understand why LWE, RLWE, and lattice-based schemes can all be expressed through vectors, matrices, and linear transformations.

\section{Learning goals}
After reading this chapter, you should be able to:

\begin{itemize}
  \item understand why an LWE instance can be written as $As+e=b$;
  \item see how RLWE is a structured extension of matrix-vector algebra;
  \item understand why a lattice is a discrete version of a vector space;
  \item appreciate why concepts such as Gram--Schmidt, LLL, and BKZ appear later in the story.
\end{itemize}

The chapter is organized as follows:

\section{Vector}
In high school algebra, a vector is often seen as a coordinate pair such as $(1,2)$. In cryptography, however, a vector is better viewed as a structured container of data. For instance, a secret key in a scheme such as Kyber may be represented as a vector of many field elements.

A typical object may look like

\[
s = \begin{bmatrix}2\\5\\1\\7\end{bmatrix},
\]

and in a practical scheme one may have

\[
s \in \mathrm{GF}(3329)^{256}.
\]

That means the secret is a vector of length $256$ whose entries lie in a finite field.

\subsection{Sage experiment: creating a vector}

\begin{lstlisting}[language=Python]
F = GF(17)
v = vector(F, [1, 2, 3])
v
\end{lstlisting}

The output is

\begin{lstlisting}[language=Python]
(1, 2, 3)
\end{lstlisting}

To inspect its type, use:

\begin{lstlisting}[language=Python]
type(v)
\end{lstlisting}

In Sage, this is often reported as a module element rather than a plain vector type. This is not an accident: when we later discuss module-LWE, the same object will reappear in a more general algebraic setting.

\subsection{Vector addition}

\begin{lstlisting}[language=Python]
a = vector(F, [1, 2, 3])
b = vector(F, [5, 6, 7])
a + b
\end{lstlisting}

The result is

\begin{lstlisting}[language=Python]
(6, 8, 10)
\end{lstlisting}

If the base field were $\mathrm{GF}(7)$ instead, then $6 + 5 = 4$ modulo $7$.

Over $\mathbb{R}$ or $\mathbb{Q}$, vector addition also has the familiar geometric picture shown in Figure~\ref{fig:vector-addition}: place both vectors tail to tail at the origin, and their sum is the diagonal of the parallelogram they span.

\section{Vector space}
A vector space is a set of objects that can be added together and multiplied by scalars in a consistent way. For cryptography, the important point is that a vector space is the collection of all valid vectors of a given type.

For example,

\[
\mathrm{GF}(17)^2
\]

contains all pairs of elements from the finite field $\mathrm{GF}(17)$. There are $17^2$ such vectors in total.

\subsection{Sage experiment: a vector space over a finite field}

\begin{lstlisting}[language=Python]
V = VectorSpace(GF(17), 2)
V
\end{lstlisting}

This creates a two-dimensional vector space over $\mathrm{GF}(17)$. A random element can be generated by:

\begin{lstlisting}[language=Python]
V.random_element()
\end{lstlisting}

\section{Basis}
A basis is a collection of vectors from which every vector in the space can be built by linear combination. In the usual two-dimensional case, the vectors

\[
(1,0), \quad (0,1)
\]

form the standard basis. Any vector $(a,b)$ can be written as

\[
a(1,0) + b(0,1).
\]

Another equally valid basis is given by

\[
(2,1), \quad (1,1).
\]

The important idea is that the same vector space can be described by many different bases.

\subsection{Sage experiment: two different bases}

\begin{lstlisting}[language=Python]
B = Matrix(GF(17), [[1, 0], [0, 1]])
B2 = Matrix(GF(17), [[2, 1], [1, 1]])
\end{lstlisting}

Later, the comparison of good and bad bases will become central in lattice reduction.

\section{Linear independence}
Two vectors are linearly independent if neither can be expressed as a scalar multiple of the other. For example, $(1,0)$ and $(0,1)$ are independent, but $(1,2)$ and $(2,4)$ are not, since the second is just twice the first.

\subsection{Sage experiment: checking rank}

\begin{lstlisting}[language=Python]
A = Matrix(GF(17), [[1, 2], [2, 4]])
A.rank()
\end{lstlisting}

The result is $1$, meaning that the matrix has only one independent direction.

\section{Matrix}
Matrices are the main objects that connect vectors and linear transformations. In later chapters, the central equation for LWE will appear in the form

\[
A s + e = b,
\]

where $A$ is a matrix, $s$ is a secret vector, $e$ is an error vector, and $b$ is the observed value.

\subsection{Sage experiment: matrix-vector multiplication}

\begin{lstlisting}[language=Python]
F = GF(17)
A = Matrix(F, [[1, 2], [3, 4]])
v = vector(F, [5, 6])
A * v
\end{lstlisting}

This reveals how linear transformations act on vectors, and it is the first step toward understanding LWE.

Underneath the single command \texttt{A * v}, Sage runs exactly the double loop of Algorithm~\ref{alg:matvec}. This computation is foundational for the rest of the book: it is the same loop that computes $As$ in the LWE equation $As+e=b$, and later, in ring form, the same loop reappears as the schoolbook polynomial multiplication used for RLWE and Kyber.

\begin{algorithm}[H]
\caption{Matrix--Vector Product}
\label{alg:matvec}
\begin{algorithmic}[1]
\Require Matrix $A \in \mathbb{F}^{m\times n}$ with entries $A_{i,j}$; vector $v \in \mathbb{F}^n$
\Ensure $w = Av \in \mathbb{F}^m$
\For{$i = 1,\dots,m$}
    \State $w_i \gets 0$
    \For{$j = 1,\dots,n$}
        \State $w_i \gets w_i + A_{i,j}\, v_j$
    \EndFor
\EndFor
\State \Return $w$
\end{algorithmic}
\end{algorithm}

\section{Why matrix multiplication matters}
This is the key cryptographic intuition. If we had only

\[
b = As,
\]

then the problem would be an ordinary linear system and could be solved by Gaussian elimination. The introduction of an error term,

\[
b = As + e,
\]

turns the problem into the learning with errors problem. In suitable parameter regimes, this becomes the hard computational problem that underlies many lattice-based cryptosystems.

\subsection{Experiment 4: the same vector in different bases}
This helps build an important intuition: the vector itself does not change, but its coordinate description changes when the basis changes. This idea is central to lattice geometry, Gram--Schmidt orthogonalization, LLL, and BKZ.
